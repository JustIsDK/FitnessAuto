# FitnessAuto 界面规范

构建 `20261009.4` 的界面参考 [emilkowalski/skills 的 apple-design](https://github.com/emilkowalski/skills/tree/main/apple-design)。该技能主要面向 Web；本项目将字体层级、及时反馈、留白和克制动效等原则应用到原生 SwiftUI。

## 视觉与交互

- 使用系统分组背景和卡片，统一青绿色强调色；颜色随浅色、深色模式调整。
- 页面依次呈现标题、关键数据、主要操作与辅助说明。诊断和实验设置放在可展开区域。
- 使用系统字体和动态字号。速度、坡度、体重使用等宽数字，避免数值更新时横向跳动。
- 主要按钮采用统一圆角和至少 52 点高度；列表采用原生分组样式，保留滚动、表单、弹窗的系统行为。
- 按下按钮立即显示反馈；启用“减少动态效果”时关闭缩放反馈。蓝牙状态刷新不添加整页动画。
- 图标使用 SF Symbols，并为仅有图标的操作提供辅助功能说明。

## 页面结构

底部 Tab 分为“训练”“计划库”“体重管理”“运动记录”四个主区域。训练首页突出实时速度、坡度、连接状态和计划控制；其余三个区域各自承担计划编辑、体重测量和健康记录。体重页突出测量结果，个人资料和设备实验设置按需展开。运动记录页保留健康授权与同步入口，并提供清晰的空记录提示。

复用组件位于 `TreadmillFTMSProbe/AppDesign.swift`。新增页面优先使用这些组件与语义颜色，避免另建一套按钮、卡片或数字字体。

## 验证

构建和现有数据检查可以验证编译及数据逻辑；真机还需检查长标题、大字体、深色模式、出生年月滚轮，以及训练运行时的状态更新。视觉改动不作为蓝牙控制或健康写入验证的替代。
