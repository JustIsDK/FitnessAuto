## 一、训练页改动

### 1. 运行态布局

训练卡片按下面顺序显示：

1. 跑步机名称和右侧连接状态。
2. 当前速度、当前坡度。这两个数值仍来自设备实时状态，不能替换成计划目标。
3. 计划选择器。
4. 开始／停止主按钮。
5. 同一行显示“本阶段剩余 mm:ss”和“已进行 mm:ss”。“已进行”放在进度条上方，使用等宽数字，防止刷新时宽度跳动。
6. 总计划进度条。进度按计划时间轴计算，并在阶段边界绘制小圆点。
7. 目标卡，显示下一阶段的速度和坡度；存在下一阶段时可点击跳转。
8. “查看完整阶段表”。阶段表继续承担跳转到任意阶段的功能。

运行态示意：

```text
停止训练
本阶段剩余 00:39                         已进行 00:01
━━━━━━━━●━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
下一阶段目标 3.3 km/h · 坡度 0%       ›
查看完整阶段表
```

### 2. 移除和保留

- 移除正常准备控制连接、启动倒计时、等待运行确认及停止过程中的短暂说明文案。启动状态仍保留在状态模型中；启动超时、启动失败、断开和恢复失败必须继续显示可操作的错误提示。
- 移除独立的“下一阶段”按钮和单独的“下一阶段”行。
- 下一阶段的跳转功能合并进目标卡。目标卡的辅助功能标签必须明确为“跳到下一阶段”。
- 阶段表仍支持跳转到任意阶段，沿用现有 `jumpToStage(at:)`、设备能力校验、串行写入和回执门槛。
- 顶部实时速度和坡度保持现状，目标卡只表示将要执行的计划目标，不能让用户误认为是设备当前值。

### 3. 进度节点规则

- 进度条的填充比例使用 `planElapsed / plan.duration`，不使用实际运动累计时间。
- 在每个阶段的累计开始位置绘制稳定节点。首端 `0` 和末端 `duration` 不重复绘制端点节点；阶段为 0 秒或多个阶段非常接近时合并节点，避免重叠成一个不可辨认的点。
- 例如总时长 20 分钟、第二阶段从第 2 分钟开始，节点位于进度条的 `10%` 处。
- 节点由稳定的阶段 ID 生成，蓝牙轮询只更新数值，不重建节点身份，不添加隐式动画，因此轮询期间不能闪烁。
- 每个节点提供无障碍描述，例如“第 2 阶段边界，计划时间 02:00”。节点本身不承担跳转操作，跳转统一通过目标卡或阶段表完成。

### 4. 目标卡状态

| 状态 | 展示 | 是否可点击 |
|---|---|---|
| 运行中且存在下一阶段 | “下一阶段目标 速度 · 坡度”及箭头 | 复用 `canJumpNextStage`，可点击时调用 `jumpToNextStage()` |
| 最后阶段 | “最后阶段目标”及末阶段参数 | 否 |
| 启动中、暂停恢复、停止中、停止未确认 | “当前阶段目标”及当前参数 | 否 |
| 断开、状态过期、目标写入/确认中 | 保留目标，但显示不可用状态 | 否，待现有门槛恢复 |
| 空闲 | 不显示跳转操作 | 否 |

点击目标卡后：

1. 只排入现有蓝牙串行写入队列，不绕过控制权、状态新鲜度和设备范围校验。
2. 写入尚未确认时禁用目标卡，正常状态查询不应造成周期性禁用或闪动。
3. 回执成功后更新目标卡和阶段表；跳转不增加实际运动累计时间。
4. 写入失败或断开时保留当前阶段，提示失败原因，恢复后允许重试。

### 5. 启动和停止兼容规则

本次只改变布局和下一阶段入口，不改变现有启停契约：启动仍需设备运行确认；停止以对应停止指令写入成功为完成条件，不等待额外停机查询。停止中和停止未确认状态不能从目标卡发送新的阶段命令。

## 二、运动记录详情和分享图片

### 1. 入口和页面

- 在“运动记录 → 本机运动记录”点击一条记录，进入“运动详情”页面；整行都可点击，删除手势和同步按钮继续保持独立操作。
- 详情页右上角提供系统分享按钮，触摸区域至少 44×44 pt，辅助功能标签为“分享运动记录图片”。
- 分享按钮生成一张 PNG 图片并打开系统 Share Sheet。分享对象是图片文件，不是当前页面截图，也不直接分享 JSON、纯文本或 PDF。
- 图片生成失败时留在详情页，显示错误提示并可重试；不影响本机记录和健康同步状态。

### 2. 分享图片内容

采用简洁白底卡片、绿色跑步图标、黑色主数据和灰色辅助数据。保持固定内容顺序：

1. 运动图标和计划标题，例如 `M4`。
2. 日期和开始时间，例如 `10 月 15 日 11:52`。
3. 运动类型和时长，例如 `室内步行 · 28:08` 或 `室内跑步 · 28:08`。
4. 距离，例如 `距离 2.46 km`。
5. 消耗热量，例如 `消耗热量 182 kcal`。

图片内容只使用 `WorkoutRecord` 已保存的数据；不重新查询跑步机，不在分享时修改记录。距离或消耗热量缺失时显示 `—`，不伪造数值。标题过长时最多显示一行并截断，日期按设备当前语言和时区格式化。

输出尺寸固定为 1080×1350 px，适合聊天和社交平台预览；文字使用动态计算布局，保证长标题、0 值和缺失值不重叠。图片应包含清晰的对比度，不依赖颜色单独传递数据。

### 3. 实现边界

- 使用 SwiftUI `ImageRenderer` 生成独立的分享卡片 View，再写入临时 PNG URL，通过 `UIActivityViewController` 交给系统。
- 分享卡片和详情页共用格式化函数，避免页面显示值与图片值不一致。
- 临时文件至少保持到分享回调结束；取消分享后清理，不删除本机记录。
- 暂不把心率、阶段明细、苹果健康来源和诊断日志放进分享图；后续若增加字段，需另行更新图片版本和验收清单。

## 三、测试与验证流程

### A. pytest 门槛

实现后新增可被 pytest 自动收集的测试文件，例如 `Tests/test_training_and_share_design.py`。已有 `verify_*.py` 继续独立运行，并由 pytest wrapper 显式调用；不能因为文件名不符合 pytest 默认收集规则而漏测。

每次修改必须满足：

```bash
.venv/bin/python -m pytest -q
python3 Tests/verify_workout_data.py
python3 Tests/verify_training_sync.py
```

pytest 必须 0 failures、0 errors 才算通过。至少覆盖：

- 20 分钟计划在 0、2、20 分钟的进度比例和节点位置。
- 多阶段、0 秒阶段、相邻阶段节点合并和稳定 ID。
- 首阶段、中间阶段、最后阶段的 next 目标和可点击门槛。
- 目标卡跳转不改变实际运动累计时间；查询、写入确认、断连期间的队列行为。
- 正常启动不渲染等待倒计时文案，启动失败仍渲染错误反馈。
- 记录详情格式化、距离/热量缺失显示 `—`、长标题截断和分享卡数据与原记录一致。

### B. 局部 UI 测试

使用专用模拟器和现有 `Tests/run_changed_ui.py`，只检查本次改动及周边约 10%，不做全量 UI 审查：

- 运行中段：`本阶段剩余` 和 `已进行` 在进度条上方；进度条有阶段节点。
- 目标卡显示下一阶段速度、坡度；不存在独立“下一阶段”按钮。
- 点击目标卡后目标值和剩余阶段更新，实际“已进行”不跳变。
- 最后阶段目标卡只读；启动中、暂停、停止中、停止未确认时不可跳转。
- 正常运行没有“等待跑步机倒计时”常驻文字；启动错误场景仍有提示。
- 连续刷新状态 10 秒，节点、目标卡和按钮不闪烁、不发生整卡重排。
- 运动记录点击进入详情页；分享按钮可见、可访问，点击后生成预览图片。
- 分享图包含标题、日期时间、类型、时长、距离、消耗热量；缺失指标显示 `—`，长标题不越界。
- 浅色、深色、动态字体和窄屏各检查一次；分享按钮和整行触摸区域不小于 44 pt。

### C. 功能子代理验证

功能测试代理只检查训练阶段跳转、启动/停止回归、运动记录详情数据和 PNG 生成，不扩展到其他 Tab。重点确认：

- 目标卡写入的确是下一阶段参数，实时设备值没有被目标值覆盖。
- 写入成功、失败、超时、断连和恢复路径符合现有队列契约。
- 分享图从指定 `WorkoutRecord` 稳定生成，取消分享不删除记录，重复分享结果一致。

### D. UI 子代理验证

UI 测试代理只检查训练卡、阶段节点、运动记录详情和分享预览的布局及交互；范围限本次改动及周边 10%。必须返回模拟器截图或 XCTest 结果，并确认没有独立 next 按钮、倒计时常驻文案和进度条上方布局回退。

### E. 真机验收

模拟器只能验证布局、状态和图片生成，不能代替跑步机 BLE 或苹果健康验收。真机需补做：

- 真实跑步机在首阶段、中间阶段、最后阶段点击目标卡，确认速度和坡度实际变化。
- 断开、回前台、目标写入失败后，目标卡不会误发命令，恢复后可以重试。
- 真实运动记录进入详情页并通过系统分享菜单发到“信息”或“文件”，接收端能打开图片且内容完整。
- 在未提供距离或热量、长计划名、大字号、深色模式下再次分享，图片不截断关键字段。

## 四、完成判定

只有以下条件全部满足，才报告本次改动完成：

- pytest 全绿，相关 `verify_*.py` 全绿。
- 功能子代理和 UI 子代理均返回通过结果；两者都只覆盖改动范围及周边 10%。
- 模拟器局部 UI 测试通过，截图符合本文布局。
- 真机跑步机和系统分享流程完成，且未引入现有启停、阶段跳转、健康同步和删除记录回归。
