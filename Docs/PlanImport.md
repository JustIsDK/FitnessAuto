# 计划导入格式 v1

后续在本项目中编写或生成训练计划，请按本规则生成 UTF-8 编码的 `.json` 文件。可以用 Mac 的 AirDrop、iCloud Drive 等将文件放入 iPhone 的“文件”APP，然后在 FitnessAuto 的 **计划库 → 导入计划** 选择文件。导入后在首页选择计划，启动前核对完整阶段表。

## 完整示例

仓库中的 [Examples/plan-import.json](../Examples/plan-import.json) 可直接导入，是一套 3 分钟低速测试计划：

```json
{
  "format": "fitnessauto.plan",
  "version": 1,
  "plans": [
    {
      "title": "3 分钟导入测试",
      "steps": [
        { "title": "热身", "durationSeconds": 60, "speedKmh": 1.0, "inclinePercent": 0 },
        { "title": "小幅调节", "durationSeconds": 60, "speedKmh": 1.5, "inclinePercent": 1 },
        { "title": "放松", "durationSeconds": 60, "speedKmh": 1.0, "inclinePercent": 0 }
      ]
    }
  ]
}
```

## 字段与限制

所有下列字段必填；字段名区分大小写。JSON 不允许注释、尾逗号、`NaN`、`Infinity` 或把数字写成字符串。

| 位置 | 字段 | 类型及规则 |
| --- | --- | --- |
| 顶层 | `format` | 字符串，必须是 `fitnessauto.plan` |
| 顶层 | `version` | 整数，当前必须是 `1` |
| 顶层 | `plans` | 数组，每个文件 1–50 套计划 |
| 每套计划 | `title` | 1–100 个字符，不能仅含空白 |
| 每套计划 | `steps` | 数组，1–100 个阶段，按执行顺序排列 |
| 每个阶段 | `title` | 1–100 个字符，不能仅含空白 |
| 每个阶段 | `durationSeconds` | 整数秒，1–3600，不能用小数或分钟单位 |
| 每个阶段 | `speedKmh` | 数字，1.0–18.0 km/h，步进 0.1 |
| 每个阶段 | `inclinePercent` | 整数百分比，0–25，例如 `8` 表示 8% |

每套计划总时长不超过 14400 秒（4 小时），文件不超过 1 MiB（1,048,576 字节）。开始训练前还会核对跑步机实际支持范围；导入成功不代表所有目标都已在真机上测试。

## 时间、编号和批量行为

- 不填写 `id`、`start` 或结束时间。APP 从第 0 秒开始累计 `durationSeconds`，自动生成连续阶段的起始时间及编号。
- 循环必须展开为完整阶段数组，例如重复四轮就写出四轮所有阶段；v1 不支持循环、条件或表达式。
- 多套计划放在同一个 `plans` 数组中。APP 验证全部计划后一次保存；任意一套无效，整批不导入。
- 导入会添加自定义计划，不覆盖内置或已有计划。同名计划允许存在；重复导入同一文件会新增副本，可以在计划库删除。
- 未声明的额外字段会被忽略，不能改变执行行为。避免额外字段，防止误以为 `repeat`、`start` 等会被执行。
- 训练、启动、停止或暂停计划期间不开放计划库编辑与导入。请先结束当前计划。
- 导入后可继续编辑、排序或删除阶段。保存时重新计算起始时间。

## 为本项目生成计划时的约定

1. 从来源逐项确认阶段名称、时长、速度和坡度，单位分别是秒、km/h、%。
2. 保留来源给出的热身、重复轮次和放松阶段；不擅自修改坡度或速度。
3. 按执行顺序展开全部阶段，写入上述 v1 格式；一次提供多套方案时使用一个 `plans` 数组。
4. 核对每套总时长、阶段范围和步进，提供完整 JSON 文件，而非只在聊天中给表格。
5. 在交付说明中列出每套总时长，说明尚未验证的真机目标。

测试：`python3 Tests/verify_workout_data.py` 会使用实际 Swift 导入器读取仓库示例，并验证错误版本、错误字段、非法阶段和整批拒绝行为。
