## 1. 训练页结构

一个分组卡片从上到下排列：

1. “跑步机”与右侧连接状态按钮；点击打开设备列表弹窗。
2. 当前速度、当前坡度并排。数据来自设备，不能用目标值假装实时值。
3. “选择计划”选择器；自定义计划在内置计划前，顺序与计划库一致，记忆上次选择。编辑已有自定义计划保持原位置，不移动到末尾。
4. 唯一的主要操作按钮：开始／停止／正在停止／重试停止。
5. 只在实际连接阻断、中断恢复或错误时出现状态说明；正常准备、启动倒计时、运行确认和停止过程不追加临时说明。中断恢复时显示“继续训练”。
6. 空闲时显示计划总时长；训练时同一行展示“本阶段剩余 mm:ss”和“已进行 mm:ss”，窄屏及大字号放不下时上下排列，均位于进度条上方。
7. 训练中显示 8 点粗进度条，节点按阶段开始时间占总时长比例排布。相距不足 12 点的节点合并显示；不绘制首尾端点。
8. 运行中目标卡显示下一阶段速度和坡度，点击跳转；无独立“下一阶段”按钮。最后阶段显示只读“最后阶段目标”。非运行态只读展示当前目标。
9. 默认折叠的“查看完整阶段表”；展开后显示阶段名称、时间段、速度、坡度与当前阶段标记。

移除：重复的选中计划大标题、自动调节副标题、“训练计划”模块标题、重复的当前阶段标题和目标行、正常运行时重复的状态消息、常驻训练须知、“暂停自动调节”、单独的“跳转到指定阶段”入口及说明、单独的“重试停止跑步机”按钮。

顶部原生导航栏“训练”保留。进度条按计划时间轴计算；“本阶段剩余”按阶段边界计算；“已进行”按实际计划运行计时累计，暂停期间不增加，跳转阶段不改变它。运动记录仍按独立的设备运行观测累计，可能包含开始计划前已经运行的时段。

## 2. 主要按钮状态契约

状态判断优先级：停止中 > 停止发送未确认 > 启动中 > 运行中 > 中断暂停 > 空闲。

| 状态 | 主按钮 | 行为与退出条件 |
|---|---|---|
| 空闲、未连接或控制未就绪 | 开始训练（禁用） | 显示阻断原因；初次打开仍需手动连接 |
| 空闲、控制就绪 | 开始训练（强调色） | 点击发送启动流程；不用提前在面板启动 |
| 启动倒计时／待确认 | 停止训练（红色） | 保留停止能力；设备确认运行后才计入正常训练 |
| 运行中 | 停止训练（红色） | 点击发送停止指令，写入成功后立即结束计划 |
| 中断暂停 | 停止训练（红色）+ 次要“继续训练” | 连接未就绪时禁用；恢复需复用后端确认流程 |
| 停止中 | 正在停止…（红色、进度圈、禁用） | 防止重复点击；仅等待对应 BLE 写入回执 |
| 停止指令发送失败／未确认 | 重试停止（红色） | 同一个按钮重试；断连时禁用并提示实体停止键；禁止开始新计划 |
| 停止指令写入成功 | 开始训练 | 恢复空闲布局，按后端规则保存实际运动记录 |

- 启动仍需设备运行状态确认。停止按用户要求，以对应 BLE 写入成功结束流程，不查询或等待停机状态；文案使用“停止指令已发送”，实时速度和坡度仍只展示设备数据。
- 启动后到停止指令写入成功前禁用计划选择，避免切换正在执行的计划。
- “继续训练”仅用于已有中断恢复流程，不新增手动暂停入口。
- 保留正在执行计划的前后台恢复逻辑；没有进行中计划时不恢复自动连接。
- 异常提示不能为追求简洁而隐藏；点击开始但校验失败时必须有反馈。

## 3. 阶段跳转

- 下一阶段目标卡调用现有 `jumpToNextStage()`；最后一个阶段只读。启动、暂停及停止期间不可跳转。
- 运行中展开阶段表，点击某一行调用 `jumpToStage(at:)`，从该阶段开头执行参数；点击当前阶段同样重置到该阶段开头。
- 继续使用 `canJumpStage` / `canJumpNextStage` 防止连接未就绪、状态过期或目标尚未确认时跳转。正常保活查询不使按钮临时禁用；如果状态查询写入尚未确认，跳转目标排入原串行写入队列，回执后执行。目标写入／确认期间仍禁用跳转，停止操作清除待发送跳转。
- 空闲、准备启动、中断暂停和停止期间，阶段表仅展示，不能点击跳转。
- 保留设备能力范围校验、指令排队及实际运动计时；本次未改变计划导入格式。

## 4. BUG-001：删除确认浮在运动趋势图上

### 复现与原因

在“运动记录 → 本机运动记录”左滑某条记录并点击删除，旧版使用挂在整个 List 上的 `confirmationDialog`，在截图中的系统呈现方式下，弹出层箭头落到上方曲线图，无法明确对应哪条记录。

### 目标设计

- 应改用居中的原生 `.alert`，不依赖图表或行的锚点。
- 标题：“删除这条运动记录？”
- 正文：记录名称、开始日期时间、运动时长以及删除范围。
- 两个明确操作：“取消”和红色“删除”；没有默认直接删除和全滑删除。
- 左滑删除与长按“删除运动记录”使用同一确认流程。
- 未同步记录：仅删除本机这一条，不请求健康权限。
- 已同步记录：删除本 APP 写入的对应健康数据，再删除本机记录；不删除其他 APP 数据。
- 删除处理中禁用记录的删除和写入操作并显示进度；失败保留本机记录及错误提示，允许重试。
- 完成后列表与趋势图由同一 records 数据源更新；重启不应恢复已删除记录。
- 与“可能是同一段运动”健康重复写入提醒共用一个 alert 呈现器，保留取消写入／仍然写入行为，避免两个 alert 修饰器争用。

## 2026-10-15 实现说明

- 启动、运行和正常停止过程不在训练卡输出临时状态说明；启动确认仍在后台按原规则执行，错误及恢复提示保留。

- 分享字段：计划名、开始时间、运动类型、实际记录时长、距离和消耗热量；缺失指标显示“—”，零值仍显示 0。
- PNG 固定为 1080×1350 白底，深色模式下仍使用浅色渲染，取消或关闭分享后清理临时文件。
- 规则与共用格式化位于 `WorkoutData.swift`，图片和详情页在 `WorkoutShare.swift`。
- 定向测试和真机待验项目见 [本次设计规范](Design/TrainingAndWorkoutShare-20261015.md)。
