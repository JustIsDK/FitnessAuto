## 1. 训练页结构

一个分组卡片从上到下排列：

1. “跑步机”与右侧连接状态按钮；点击打开设备列表弹窗。
2. 当前速度、当前坡度并排。数据来自设备，不能用目标值假装实时值。
3. “选择计划”选择器；自定义计划在内置计划前，顺序与计划库一致，记忆上次选择。
4. 唯一的主要操作按钮：开始／停止／正在停止／重试停止。
5. 仅在准备启动、连接阻断、恢复或错误时出现的状态说明；中断恢复时显示“继续训练”。
6. 总时长与阶段数。
7. 计划进行时显示进度条、已进行时间与计划剩余时间，以及一行“目标 5.0 km/h · 坡度 0%”。
8. 运行中显示“下一阶段”。
9. 默认折叠的“查看完整阶段表”；展开后显示阶段名称、时间段、速度、坡度与当前阶段标记。

移除：重复的选中计划大标题、自动调节副标题、“训练计划”模块标题、重复的当前阶段标题和目标行、“本阶段剩余”、正常运行时重复的状态消息、常驻训练须知、“暂停自动调节”、单独的“跳转到指定阶段”入口及说明、单独的“重试停止跑步机”按钮。

顶部原生导航栏“训练”保留。计划总时长与计划进度不等于运动记录中的实际运动时长；跳转阶段不会凭空增加健康记录。

## 2. 主要按钮状态契约

状态判断优先级：停止中 > 停止未确认 > 启动中 > 运行中 > 中断暂停 > 空闲。

| 状态 | 主按钮 | 行为与退出条件 |
|---|---|---|
| 空闲、未连接或控制未就绪 | 开始训练（禁用） | 显示阻断原因；初次打开仍需手动连接 |
| 空闲、控制就绪 | 开始训练（强调色） | 点击发送启动流程；不用提前在面板启动 |
| 启动倒计时／待确认 | 停止训练（红色） | 保留停止能力；设备确认运行后才计入正常训练 |
| 运行中 | 停止训练（红色） | 点击走已有停机流程，不直接假定停机成功 |
| 中断暂停 | 停止训练（红色）+ 次要“继续训练” | 连接未就绪时禁用；恢复需复用后端确认流程 |
| 停止中 | 正在停止…（红色、进度圈、禁用） | 防止重复点击；等待设备状态确认 |
| 停止失败／未确认 | 重试停止（红色） | 同一个按钮重试；断连时禁用并提示实体停止键；禁止开始新计划 |
| 已确认停止 | 开始训练 | 恢复空闲布局，按后端规则保存实际运动记录 |

- 禁止把 BLE 写入成功、命令回显或固定延时当作跑步机已经启动／停止。
- 启动后到停止确认前禁用计划选择，避免切换正在执行的计划。
- “继续训练”仅用于已有中断恢复流程，不新增手动暂停入口。
- 保留正在执行计划的前后台恢复逻辑；没有进行中计划时不恢复自动连接。
- 异常提示不能为追求简洁而隐藏；点击开始但校验失败时必须有反馈。

## 3. 阶段跳转

- “下一阶段”调用现有 `jumpToNextStage()`；最后一个阶段不可点击。
- 运行中展开阶段表，点击某一行调用 `jumpToStage(at:)`，从该阶段开头执行参数；点击当前阶段同样重置到该阶段开头。
- 继续使用 `canJumpStage` / `canJumpNextStage` 防止连接未就绪、状态过期、指令忙碌时发送。
- 空闲、准备启动、中断暂停和停止期间，阶段表仅展示，不能点击跳转。
- 保留设备能力范围校验、指令排队及实际运动计时；本次未改变计划导入格式。

## 4. BUG-001：删除确认浮在运动趋势图上

### 复现与原因

在“运动记录 → 本机运动记录”左滑某条记录并点击删除，旧版使用挂在整个 List 上的 `confirmationDialog`，在截图中的系统呈现方式下，弹出层箭头落到上方曲线图，无法明确对应哪条记录。

### 目标设计

- 应改用居中的原生 `.alert`，不依赖图表或行的锚点。
- 标题：“删除这条运动记录？”
- 正文：记录名称、开始日期时间、运动时长以及删除范围。
- 两个明确操作：“取消”和红色“删除”；没有默认直接删除和全滑删除。
- 左滑删除与长按“删除运动记录”使用同一确认流程。
- 未同步记录：仅删除本机这一条，不请求健康权限。
- 已同步记录：删除本 APP 写入的对应健康数据，再删除本机记录；不删除其他 APP 数据。
- 删除处理中禁用记录的删除和写入操作并显示进度；失败保留本机记录及错误提示，允许重试。
- 完成后列表与趋势图由同一 records 数据源更新；重启不应恢复已删除记录。
- 与“可能是同一段运动”健康重复写入提醒共用一个 alert 呈现器，保留取消写入／仍然写入行为，避免两个 alert 修饰器争用。

## 5. 实现位置与效果图约束

| 文件 | 职责 |
|---|---|
| `ContentView.swift` | 卡片排布、主按钮、阶段表、错误提示；`TreadmillStatusCard` 和 `TrainingPlanControls` 为运行页面与模拟器截图共同使用的组件 |

| `WorkoutRecorder.swift` | 删除弹窗、重复记录提醒及原有异步删除流程 |
| `Tests/verify_workout_data.py` | 状态优先级及停机未确认时禁止启动的规则检查 |

效果图来自实际 SwiftUI 组件。训练各状态由 Debug 模拟器的 `--training-design idle/running/stopping/stopUnconfirmed/paused` 注入示例数据；该入口不编入真机，操作不发送蓝牙报文，不能代替真机启停验证。删除与导入截图来自真实记录页和导入页，使用测试数据。HTML 演示仍保留为交互说明，以代码截图和本页状态契约为验收依据。

- [x] 运行中：红色停止按钮、目标仅一行，无旧暂停／独立跳转入口。
- [x] 开始后按钮变停止，点击停止变“正在停止…”且不可重复点击。
- [x] 停止未确认显示“重试停止”，没有“开始训练”。

- [x] 下一阶段及阶段表点击更新对应目标。

- [x] 确认删除仅移除所选记录，其他记录保留，重启后结果持久化。

### 真机验收（需跑步机／健康数据，不能由效果图替代）

- [ ] 连接静止跑步机后直接开始，倒计时后确认运行并执行第一阶段。
- [ ] 运行中停止，只有收到停机状态才恢复“开始训练”。
- [ ] 启动倒计时中停止也能正确取消；失败显示重试，不允许开始新计划。
- [ ] 断连、电话打断、返回前台的已有恢复机制可用；空闲启动仍手动连接。
- [ ] 下一阶段、任意阶段跳转实际调整速度和坡度；运动记录不包含跳过的时间。
- [ ] 已同步记录删除后，苹果健康中本 APP 对应数据消失，其他来源不受影响。
- [ ] 健康删除失败／超时保留本机记录，提示原因，页面仍可操作。
- [ ] 健康重复提醒中的取消／仍然写入可用。
- [ ] 真机大字号、浅色模式下按钮和目标不截断；删除弹窗位置明确。
