# 外部 JSON 文件导入

## 目标

用户通过 AirDrop 收到课程 JSON，或在“文件”等 APP 中分享 JSON，选择 FitnessAuto 后打开解析并导入，不必再到计划库手动寻找文件。继续保留原有“计划库 → 导入计划”入口。

已实现 iPhone 文档关联、统一文件路由和导入确认页。数据格式继续使用 [PlanImport.md](PlanImport.md) 的 `fitnessauto.plan` v1，不支持任意 JSON 自动推断为课程。

## 实现路径与平台边界

1. 在 **iPhone target** 的文档类型中声明 `public.json`，角色 Viewer、处理优先级 Alternate；使用系统既有 JSON 类型，不发明新的通用 JSON UTI。不改默认文件归属，不修改 Watch target。
2. 在 App／根视图统一处理文件 URL 打开事件（`onOpenURL`），包括冷启动、后台恢复和已打开状态。接到文件后切换到“计划库”，打开导入结果页。
3. 接入现有 `PlanImportDocument.decode` 与 PlanLibrary 的原子保存流程；外部入口、应用内选文件必须共用解析与验证规则，不能各写一套解析器。
4. 必须真机验证“文件 → 分享 → 更多 → FitnessAuto”和 AirDrop 接收后的打开入口是否均可达。系统措辞可能是“用 FitnessAuto 打开”或“拷贝到 FitnessAuto”，不能只用模拟器 URL 打开测试便认定分享入口已通过。
5. 文档类型关联提供的是“用 APP 打开文件”，不保证每个来源 APP 的标准 Share Sheet 都显示同样入口。若用户实际使用的来源 APP 只给分享扩展入口，需另行实现 Share Extension：接收 `NSItemProvider` 文件，复用校验并通过 App Group 交接待导入文件。禁止用私有 API 强行唤起主 APP；扩展不能可靠自动打开主 APP，该路径的体验需单独说明和验收。优先验证最小的文档关联路径，避免无依据新增扩展。

## 页面流程

`分享／打开 JSON → FitnessAuto → 计划库 → 解析中 → 计划摘要 → 确认导入 → 成功`

- 解析中：文件名 + 进度反馈，不展示空白页面。
- 摘要：文件名、计划数量，每套计划的名称、总时长、阶段数；主按钮“导入 N 套计划”，次按钮“取消”。没有确认前不写入计划库。
- 成功：显示“已导入 N 套计划”，返回计划库，自定义计划列表包含新记录。训练页的选择列表同步更新，但不切换正在执行的计划，不启动跑步机。
- 无效：显示“无法导入计划”、具体原因与“关闭”；保留已有计划。普通 JSON 只提示格式不匹配，不产生半成品计划。
- 重名：提示“将新增同名计划，不会覆盖已有计划”，由用户确认。不要静默覆盖、自动合并或擅自改名。
- 同一文件连续回调：一轮呈现只处理一次；后续主动重复打开允许重新预览，确认后可另存一套。导入处理中禁止重复点击。
- 训练进行中：接收并保存到临时待处理文件，提示“文件已接收，训练结束后可导入”；不自动切离训练页、不替换当前计划、不触发跑步机启停。结束后给出待导入入口；用户可取消并清理临时文件。
- 已有编辑／导入弹窗：不能把未保存编辑覆盖掉，提示存在待导入文件，待当前弹窗退出再展示。多文件到达按接收顺序排队，逐个确认；取消一项不删除其他项。

应用内选文件与外部打开统一调用 `receiveImport`，先生成预览；只有点击确认才调用 `confirmImport` 保存。暂存与解析在后台执行，30 秒超时会给出反馈；多文件按接收顺序等待。提交前记录计划 ID，重启时清理已完成的待导入项，避免保存后意外中断导致重复导入。

## 文件与状态约束

- 仅接受本地文件 URL，按需取得 security-scoped 访问，完成后释放；外部临时文件先复制到 APP 管理的暂存位置，再用于异步展示。
- 保留 1 MB 上限，以及现有计划数量、阶段数量、时长、速度、坡度校验；整批通过后原子写入，有一套失败就整批不写。
- 文件读取和 JSON 解析避免阻塞主线程；UI 状态回到主线程更新。
- ID 在最终提交时按当前库分配，避免预览期间库发生变化造成冲突；不因外部输入覆盖内置或已有计划。
- 导入成功、取消后清理对应暂存文件；读取失败可重试，报错不泄漏完整文件路径。
- 不增加自动训练、蓝牙连接或健康授权操作；不改变 bundle identifier、现有数据目录或计划 JSON 版本。
- 对超时、文件被移除、iCloud 尚未下载或权限失效，给出可理解的读取失败信息，原计划保持不变。

## 实现参考位置

- iPhone Info.plist／Xcode 文档类型声明：注册外部打开能力。
- `FitnessAutoApp.swift`／`ContentView.swift`：统一路由、切 Tab、弹窗协调。
- `PlanLibrary.swift`：待导入状态、预览、确认保存；保留现有持久化目录。
- `PlanImport.swift`：共用格式校验，不复制解析规则。
- 只有文档关联无法满足真实分享入口时，才评估新增 Share Extension target、App Group 与共享队列；不得在未测试时宣称已经支持所有来源 APP。

## 可验收 checklist

- [ ] iPhone 从 AirDrop 接收合法 JSON 后能选择 FitnessAuto，冷启动可显示摘要。
- [ ] “文件”APP 分享中的“更多”可找到 FitnessAuto 并打开文件；记录实际 iOS 版本和操作路径。
- [ ] APP 在后台时接收文件也能解析，状态与冷启动一致（冷启动和已打开状态已验证）。
- [ ] 应用内“导入计划”和外部打开得到相同摘要、校验错误和保存结果。
- [x] 摘要显示正确名称、时长、阶段数，取消不写入任何计划。
- [x] 批量导入成功后自定义列表增加对应数量；重启后保留，训练选择器可选。
- [x] 重名会提示新增副本，不覆盖旧计划；一次确认不产生重复导入。
- [x] 普通 JSON、损坏 JSON、错误版本、超 1 MB、越界参数均提示原因且不改变原计划。
- [x] 批次中一套无效，整批不写入；存储失败时显示失败，不假报成功。
- [ ] 训练进行中接收文件不改变控制流程，结束后可处理待导入文件。
- [ ] 编辑未保存／已有弹窗／连续收到多个文件时，不丢数据、不相互覆盖。
- [ ] 文件权限、云端文件或读取失败有反馈；页面不卡住，暂存文件按规则清理。
- [x] UI 审查仅覆盖导入摘要、失败、成功及相关入口；不做全量页面审查。

## 本次验证与剩余边界

已在 iOS 27 模拟器通过真实文件 URL 验证冷启动／已打开状态路由、预览取消、批量确认、重启持久化和无效文件提示；模型检查覆盖接收去重、队列顺序、取消进行中的读取、保存失败及提交中断恢复。
